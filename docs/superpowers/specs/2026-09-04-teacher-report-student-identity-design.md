# 교사 독서록 상세 학생 식별 정보 설계

## 목적

교사가 개별 독서록을 검토할 때 작성 학생을 즉시 식별할 수 있도록, 교사 상세 화면에 학생의 학급·번호·이름을 표시한다. 현재 대시보드 목록에는 학생 정보가 있으나 상세 화면에서는 사라져, 여러 독서록을 연속으로 확인할 때 불편하다.

## 확정된 화면 구성

### 상단 식별 줄

독서록 제목 아래, 날짜 줄 위에 `2학년 3반 · 12번 · 홍길동` 형식의 식별 정보를 표시한다.

- 제목보다 낮은 시각적 우선순위를 사용한다.
- 날짜와 구분되는 한 줄의 정보로 제공한다.
- 화면을 연 직후 작성자를 빠르게 확인하는 용도다.

### 본문 카드의 작성 학생 줄

독서록 내용 카드의 첫 줄에 `작성 학생  홍길동 (2학년 3반 · 12번)`을 표시한다.

- 기존 `지은이` 줄과 같은 정보 스타일을 사용한다.
- 독서 내용과 승인·반려 결정을 내리는 중에도 작성자 정보를 다시 확인하는 용도다.
- 상단과 중복되지만, 상단은 빠른 식별, 카드 안은 검토 맥락 유지라는 서로 다른 역할을 갖는다.

## 데이터와 API

교사 상세 페이지는 학생 정보가 포함된 교사용 조회 응답을 사용해야 한다.

- `book_report_entries`를 학생(`book_report_students`)과 학급(`book_report_classes`)까지 함께 조회한다.
- 응답의 `report`에 기존 독서록 필드와 `student: { id, name, number, class: { name } }`를 포함한다.
- 학생용 독서록 상세 조회의 기존 응답과 권한 동작은 변경하지 않는다. 교사 상세 화면만 교사용 엔드포인트로 전환한다.
- 조회 실패나 학생 관계 데이터가 누락된 경우, 기존 오류 처리 흐름을 유지하고 화면이 학생 정보 없이 오해를 유발하지 않도록 한다.

## 컴포넌트 경계

- `lib/types.ts`: 교사용 독서록 상세에 필요한 학생 포함 타입을 명시한다.
- 교사용 상세 API route: 인증을 확인한 뒤 독서록·학생·학급을 조합하여 반환한다.
- `app/teacher/reports/[id]/page.tsx`: 새 타입을 사용하고, 상단 식별 줄과 카드 내 작성 학생 줄을 렌더링한다.

## 테스트 및 확인

- 인증되지 않은 교사 상세 조회는 거부한다.
- 인증된 조회는 학생 이름·번호·학급을 포함한 응답을 반환한다.
- 상세 페이지에서 상단과 본문 카드에 각각 학생 식별 정보가 렌더링된다.
- 기존 교사 목록, 승인·반려, 삭제 및 학생용 독서록 상세 흐름은 회귀 없이 동작한다.

## 범위 밖

- 대시보드 목록의 학생 표시 방식 변경
- 학생 식별·로그인 체계 개편
- 독서록 데이터베이스 스키마 변경
