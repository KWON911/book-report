# 학생용 온라인 독서록 앱 설계

## 배경 / 목적
- 종이 독서록을 학생들이 자주 분실함
- 종이 독서록을 걷어서 검사하는 것이 교사에게 부담됨 → 온라인으로 제출/검사하고 싶음
- 운영 규모: 한 교실(교사 1인) 수준의 소규모 테스트용

## 사용 환경
- 웹앱 + 모바일 반응형 (PC/태블릿/스마트폰 브라우저 모두 대응)

## 인증 방식
- **학생**: 별도 회원가입/로그인 없음. 이름 + 학급 + 번호만 입력해 세션 식별 (localStorage 기반)
- **교사**: 별도 계정 없이 공유 비밀번호 1개로 접근 (소규모 테스트용으로 단순화)

## 기술 스택
- **Next.js (App Router)**: 프론트엔드 + API Route를 한 프로젝트에서 관리
- **Supabase (PostgreSQL)**: 데이터 저장. 무료 티어로 충분
- **Vercel**: 호스팅 (무료 티어)

## 데이터 모델

### classes (학급)
| 필드 | 설명 |
|---|---|
| id | PK |
| name | 학급 이름 (예: "3학년 2반") |

### students (학생)
| 필드 | 설명 |
|---|---|
| id | PK |
| name | 이름 |
| class_id | FK → classes |
| number | 번호 |

이름+학급+번호 조합으로 학생을 식별 (로그인 대체).

### book_reports (독서록)
| 필드 | 설명 |
|---|---|
| id | PK |
| student_id | FK → students |
| title | 책 제목 |
| author | 저자 |
| summary | 줄거리 |
| impression | 느낌/감상 |
| status | draft(임시저장) / submitted(제출) / approved(승인) / rejected(반려) |
| teacher_comment | 교사 코멘트 (반려 사유 등) |
| created_at | 생성일 |
| submitted_at | 제출일 |

## 화면 구성

1. **학생 홈**: 이름/학급/번호 입력 → 내 독서록 목록 조회 (상태 뱃지 표시: 임시저장/제출/승인/반려)
2. **독서록 작성/수정**: 책제목·저자·줄거리·느낌 입력. 임시저장 또는 제출 가능. 반려된 항목은 이 화면에서 수정 후 재제출
3. **교사 로그인**: 공유 비밀번호 입력
4. **교사 대시보드**: 전체/학급별 독서록 목록, 상태별 필터
5. **교사 상세보기**: 개별 독서록 확인 → 코멘트 작성 + 승인/반려 처리

## 핵심 흐름
1. 학생이 독서록 작성 → 임시저장 또는 제출
2. 교사가 대시보드에서 제출된 독서록 확인
3. 교사가 승인 또는 반려(코멘트 포함) 처리
4. 반려된 경우 학생이 목록에서 "수정하기"로 진입 → 수정 후 재제출 (status: submitted로 재변경)
5. 승인될 때까지 3~4 반복

## 범위 밖 (Out of scope)
- 학생/교사 개별 계정 및 비밀번호 관리
- 여러 학급/여러 교사를 위한 권한 분리
- 파일 첨부, 이미지 업로드
- 통계/리포트 기능
