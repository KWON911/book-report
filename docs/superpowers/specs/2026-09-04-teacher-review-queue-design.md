# 교사 검토 대기함 설계

## 목적

교사가 제출된 독서록을 연속으로 확인하고 처리할 수 있게 해, 대시보드와 상세 화면을 반복해서 오가는 시간을 줄인다.

## 범위

첫 단계에는 아래 세 기능을 함께 제공한다.

1. 대시보드의 검토 대기 건수와 대기함 진입
2. 교사 상세 화면의 이전·다음 대기 독서록 이동
3. 승인·반려 성공 후 다음 대기 독서록으로 자동 이동

반려 코멘트 템플릿, 목록 일괄 승인은 이번 단계에 포함하지 않는다.

## 사용자 흐름

1. 교사가 대시보드에서 `검토 대기 n건`을 누른다.
2. 상태가 `submitted`인 독서록만 제출 시각 내림차순으로 정렬한 대기 목록을 연다.
3. 대기 목록의 한 독서록을 열면 상세 화면에 `검토 대기 3 / 7`과 이전·다음 이동 버튼을 표시한다.
4. 교사가 승인 또는 반려한다. 반려는 비어 있지 않은 코멘트가 있어야 처리할 수 있다.
5. 처리 API가 성공하면 동일 대기 목록에서 다음 독서록을 연다.
6. 마지막 독서록을 처리하면 대시보드로 돌아간다. 대시보드의 대기 건수는 새로 불러온 결과로 갱신된다.

일반 대시보드 목록이나 직접 URL로 상세 화면을 열었을 때는 검토 대기 위치와 이전·다음 버튼을 표시하지 않는다.

## 화면 구성

### 대시보드

- 기존 필터 줄 아래에 `검토 대기 n건` 버튼을 둔다.
- `n`은 현재 교사가 조회할 수 있는 모든 `submitted` 독서록 수다. 학급·학생·상태 필터에 의해 달라지지 않는다.
- 버튼은 대기 목록의 첫 번째 독서록으로 이동한다. 대기 항목이 없으면 비활성화한다.

### 교사 독서록 상세

- 학생 식별 줄 아래에 대기함에서 열었을 때만 `검토 대기 현재번호 / 전체수`를 표시한다.
- 이전·다음 버튼은 제목 아래 또는 검토 버튼 위에 두며, 첫 항목의 이전 버튼과 마지막 항목의 다음 버튼은 비활성화한다.
- 승인·반려 버튼의 라벨은 기존대로 유지한다.
- 승인 또는 반려 요청이 진행되는 동안 이전·다음 버튼과 검토 버튼을 모두 비활성화한다.

## 데이터와 URL

- 데이터베이스 스키마를 변경하지 않는다.
- 대기 목록은 기존 교사용 독서록 조회 API에서 `status=submitted`로 가져온 데이터의 ID 배열을 사용한다.
- 상세 URL은 `?queue=<쉼표로-구분한-ID>&index=<0부터-시작하는-위치>`를 사용한다.
- 상세 페이지는 URL의 대기 ID 배열과 현재 독서록 ID가 유효할 때만 대기 내비게이션을 렌더링한다.
- URL이 비었거나 유효하지 않으면 일반 상세 화면으로 안전하게 동작한다.

## 오류 처리

- 대기 목록 조회가 실패하면 버튼을 숨기고 기존 대시보드 오류 처리 흐름을 유지한다.
- 검토 처리 API가 실패하면 현재 상세 화면에 오류를 표시하고 이동하지 않는다.
- 반려 코멘트가 공백이면 API를 호출하지 않고 입력 영역 아래에 안내를 표시한다.
- 다음 대기 독서록이 존재하지 않으면 처리 성공 뒤 대시보드로 이동한다.

## 테스트

- 제출됨 항목만 대기 목록에 포함하고 제출 시각 내림차순으로 정렬한다.
- 대기 URL이 첫 번째 항목, 중간 항목, 마지막 항목의 이전·다음 대상을 올바르게 계산한다.
- 대기 URL이 없거나 잘못되면 내비게이션을 숨긴다.
- 반려 코멘트가 공백이면 반려 요청을 보내지 않는다.
- 승인·반려 성공 시 다음 대기 항목으로 이동하고, 마지막 항목 처리 후 대시보드로 이동한다.

## 범위 밖

- 일괄 승인·일괄 반려
- 반려 코멘트 템플릿
- 알림 발송
- 학생 화면의 작성 경험 변경
